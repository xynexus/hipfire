## The model, and why C is hard

`Qwen3_5ForConditionalGeneration`, **873.4M params**. Not dense llama:

- **Gated-DeltaNet hybrid** — 24 layers, `layer_types` = 3× `linear_attention`
  then 1× `full_attention`, repeating (`full_attention_interval: 4`).
- `attn_output_gate: true` (q_proj emits `2*q_dim`), qwen3-style QK-norm.
- **`tie_word_embeddings: true`** — the embed table *is* the lm_head.
- Embedded 1-layer MTP head (`mtp_num_hidden_layers: 1`).
- VL wrapper around a `qwen3_5_text` core. **arch_id 5** (`ARCH_ID_QWEN35_DENSE`).

Parameter split (measured from the safetensors header, not config):

| component | params | share |
|---|---|---|
| `embed_tokens` `[248320, 1024]` — **tied ⇒ also lm_head** | 254.3M | **29.1%** |
| text body (24 layers) | 498.1M | 57.0% |
| vision tower | 100.6M | 11.5% |
| MTP head | 20.5M | 2.3% |

**Vision is dropped** (operator decision 2026-09-02). `hipfire-quantize` skips
the tower by default; do not pass `--include-vision`. Text scope = embed + body
+ MTP = **772.9M**.

### The bit arithmetic — this is the whole problem

`~/.hipfire/models/qwen3.5-0.8b--oq4++.hfq` already exists (776 MB, 2026-08-29).
That is **7.99 bits/weight** — not because oq4++ failed, but because
`--embed-precision` defaults to `source`, so the embed table stays bf16 at
**508 MB = 65% of the artifact**.

A bf16 embed alone costs 4068 Mbit. A 4.0 bpw budget for the whole 772.9M text
model is 3092 Mbit. **The embed alone busts a 4-bit budget by 32%.** So:

```
embed=bf16   body=oq4      7.99 bpw   772 MB   <- today's artifact
embed=q8     body=oq4      5.36 bpw   517 MB
embed=oq4    body=oq4      4.06 bpw   392 MB
embed=oq4    body=qtip3    3.44 bpw   332 MB
embed=qtip3  body=qtip3    3.13 bpw   302 MB   <- target C
```

**Sub-4-bit on this model is reachable only by quantizing the tied embed/lm_head
to 3-4 bits.** That is the one tensor prior work says to leave alone — the embed
seeds the residual *unnormalized*, so its quant error is the largest per-tensor
KLD cost in an otherwise low-bit model (`reference_embed_quant_residual_
sensitivity`), and here it is simultaneously the output head.

This is not a reason to refuse. It is the actual experiment, and it is what makes
SpinQuant and QAT load-bearing rather than decorative: rotation and recovery-FT
are precisely the levers that make a low-bit embed survivable. But it means
**target C's risk is concentrated in one tensor**, and the plan below measures
that tensor's cost before building anything for it.

## Ground truth established 2026-09-02 (verified in tree, not from memory)

Memory was **stale on two counts**. Both were checked in the source:

- **`oq3` is fully built, not "OPEN".** `quantize_oq3g256` + `oq3_ldlq_pack`
  (LDLQ at int3) + AWQ composition all exist (`codecs.rs:838`, `cli.rs:4581`).
  **But `oq3_to_oq8_combined` (`oq8_arch.rs:576`) sign-extends it to
  `DType::Oq8G256` at load — Oq3 is a DISK-ONLY format: 3 bits on disk, 8 bits
  resident, existing W8 kernels.** It shrinks the file, not VRAM, not decode.
- **`qtip3` is the only genuine 3-bit-resident format.** Real packed
  `Qtip3G256` (qt 31, 100 B/group), native `gemv_qtip3g256` kernel
  (`families/gemv.rs:498`), and the qwen35 loader already accepts qt 31
  (`qwen35/loading.rs:961`). The operator's instinct ("will probably need qtip")
  was correct. **C is a qtip3 artifact.**

Also present and usable: `--awq`/`--awq-alpha`, `--ldlq`, `--hessian`,
`--mixed-bpw` (automatic per-tensor bit allocation), `--w8-top`, `--sq-split`,
`HIPFIRE_QTIP_HESSIAN` (QTIP-LDLQ), `--tensor-format` glob overrides,
`--copy-untargeted`, `--embed-precision`.

`hipfire-train` genuinely covers this architecture — `la_block.rs`, `hybrid.rs`,
`gradcheck_deltanet`, `gradcheck_la_block`, `attn_output_gate` + QK-norm in
`loader.rs`, plus `oqplus_quant.rs`, `qtip_quant.rs`, `kv_noise.rs`, LoRA, and
`hfq_patch.rs` (the QAT-to-artifact seam).

### Confirmed missing — real build work

1. **SpinQuant is hard-blocked.** `cli.rs:9532` refuses:
   `error: --rotate is dense-llama only (arch_id 0/1); got arch_id 5`.
   The R1 pre-pass folds RMSNorm into readers and rotates residual
   readers/writers/embed using HF **llama** tensor names. A GDN hybrid needs
   `linear_attn.in_proj_qkv` / `in_proj_z` / `out_proj`, the output gate, and
   QK-norm handled.
2. **No sub-4-bit embedding gather.** `dispatch/embedding.rs` has f32, q8, q4k,
   `hfq4g256`, `hfq4g128`, bf16, f16 — **4 bits is the floor**, and
   `--embed-precision` exposes only `source|q8|bf16|f16`, so even the existing
   4-bit gather is unreachable by flag. A qtip3 gather does not exist.
3. **No calibration artifact for this model.** `/srv/hipfire/calib/` is now
   **empty**; surviving `.calib.hfq` files under `~/.hipfire/calib/` are all 2B+.
4. **QAT unproven at scale** — every recovery example (`oqplus_recovery_supra50m`,
   `kvnoise_recovery_supra50m`) is a 50M toy.

## Scheduling: overlap, don't serialize

The operator's instruction is to launch long jobs early and work while they run.
The resource split that makes this possible:

- **GPU (serialized by the `hip-gpu-0` flock):** calibration, KLD eval, serving
  checks, QAT training. Only one at a time.
- **CPU (rayon, ~80% of cores):** the quantizer's codec/LDLQ/QTIP-trellis work.
- **Free:** reading code, writing the `--embed-precision` extension, the
  SpinQuant prepass, and every unit test.

So the critical path is the **GPU queue**, and CPU quantization + code work
should fill the gaps rather than waiting.

**Verify in P0 whether `hipfire-quantize` actually touches the GPU.** `AGENTS.md`
lists it among binaries needing `hipfire lock`, which implies it does for some
codecs. If it is CPU-only for our formats, quantization overlaps GPU work freely;
if not, it joins the GPU queue and the plan below tightens. Do not assume.

Intended shape (adjust as measurements land — this is a sketch, not a contract):

```
GPU queue:  [P1 calibration] -> [P4 probe KLDs] -> [P2/P3 KLDs] -> [P7 QAT ...]
CPU:              [quantize A/B once calib lands] [qtip3 encodes] ...
Code:       [embed-precision flag] [SpinQuant prepass] [MTP probe harness]
```

**Checkpoint any training aggressively** — it is explicitly resumable across
nights, so a run that dies at hour 8 must not lose hour 7.

**Log every launch** with its pid and start time. Kill by recorded pid; never
`pkill -f`.

### P2-MTP — **Measure the MTP head's required bit budget**  *(operator-requested)*

The 1-layer MTP speculator (20.5M) is **excluded from the headline bpw** but must
stay as low as it tolerates. Its quality metric is **not** KLD — it is
**draft acceptance rate**, which is what makes it worth its bits at all.

Sweep the head independently of the body using `--tensor-format` globs on the
`mtp.` prefix (`--include-prefix mtp.` builds it as a standalone sidecar if that
is easier to score), holding the body at a fixed format:

| arm | MTP width | note |
|---|---|---|
| bf16 | 16 | control — the acceptance ceiling |
| oq8++ | 8 | |
| oq4.25++ | 4.25 | the operator's suspected collapse point |
| qtip3 | 3.13 | only if 4.25 holds up |

**Metric:** acceptance rate vs the bf16 control on the held-out slice, plus
end-to-end decode tok/s (a drafter that is accurate but slow is also worthless).
**Gate:** pick the lowest width whose acceptance is within a few points of the
bf16 control. Record the full curve in the run log either way — a measured
collapse point is a real result and directly answers the operator's speculation.
**Fallback:** if acceptance cannot be scored end-to-end tonight, keep the MTP at
oq8++ and record that the budget question is unresolved. **Do not drop the head.**

### P5 — Embed lever  *(only if P4c misses the KLD bar)*

Increasing cost; stop at the first that clears:

1. **Protect the head, quantize the gather.** The tied table serves two roles;
   `--tensor-format` + `--tensor-source` can emit an untied 4-bit gather while
   keeping a higher-precision head (or lean on the two-pass coarse lm_head tier,
   on by default — see `--no-coarse-lmhead`).
2. **`--mixed-bpw`** with the embed in scope, letting the Hessian allocate.
3. **A qtip3 embedding gather kernel** — only if 1 and 2 both miss. This is the
   "substantial new kernel code" to avoid writing blind; P4 is what justifies it.

**Fallback:** accept ~3.44 bpw (P4c) as target C. That is still <4.0 and meets
the stated goal. Do not burn the night chasing 3.13 if 3.44 clears.

### P6 — SpinQuant for the hybrid  *(experiment first)*

**Do not start by writing the deploy pre-pass.** Measure the rotation's value on
*this* model with what exists: `rotation_invariance_probe`, `learned_r1_probe`,
`learn_r1_dump`, `rotation_a4_snr_probe` in `hipfire-train/examples`.

Only if the probe shows real gain at 3 bits, extend `spinquant_r1_prepass` past
its `arch_id != 0 && arch_id != 1` gate (`cli.rs:9532`) to arch 5: fold RMSNorm
into readers and rotate residual readers/writers/embed across
`linear_attn.in_proj_qkv`, `in_proj_z`, `out_proj`, the attn output gate, and
QK-norm.

Rotation is the most principled lever for a low-bit *tied embed* specifically,
because `--rotate` already rotates the embedding — exactly the tensor P4/P5
struggle with.

**Gate:** probe shows measurable SNR/KLD gain at 3 bits on this model.
**Fallback:** skip. Mark C "no rotation" and keep the P4/P5 result.
