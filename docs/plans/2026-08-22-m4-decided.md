# §M4 — the decision, made by measurement

Status: decided 2026-08-22, nix1 / gfx1103.

§M4 ends with: *"is module granularity worth unfusing the default MoE decode
path? ... Decide before implementing; the split is not free and the fused path
is the one that ships."*

**The answer is no, and not because the trade is unattractive. On this box the
unfused path does not load at all.**

## The A/B

`HIPFIRE_QWEN35_MOE_OQ_INDEXED=0` is the existing switch: at
`qwen35/loading.rs:6466`, when the indexed path is off, routed OQ experts skip
the MoE-block repack and fall through to the generic per-tensor
`load_weight_tensor`. Same artifact, same box, same KV mode
(`Qwen3.6-35B-A3B--oq4`, kvarn, 256 experts / 40 MoE layers):

| | fused (default) | unfused (`=0`) |
|---|---|---|
| load | completes, 17.77 / 17.77 GiB, 28.8 s | **dies at layer 25 / 40** |
| payload placed at failure | — | 11.56 GiB |
| device memory at failure | — | **15.9 MiB free of 43 008 MiB** |
| decode | 22.63 tok/s | never reached |

Reproduced twice, the second time alone against confirmed-free VRAM, so it is
not the previous process failing to release.

**~11.6 GiB of payload exhausted ~43 GiB of device memory — about 3.7×
amplification.** That is overhead, not payload.

## What it means for M4

The question §M4 poses assumes unfusing is a *throughput* trade: pay some
launches and D2H, gain suspension granularity. On this artifact it is not a
trade, it is a wall. So M4 takes the branch its own text provides — qwen35 keeps
the coarse quantum, `SuperOpKind::Moe` stays one super-op, and the reason is now
a measurement rather than a preference.

**M4 is gated on §M5, not on taste.** The amplification is exactly the failure
mode `moe-expert-residency-unification.md` exists to remove — its "Why" section
opens on unpacked per-expert residency and the allocator overhead it causes, and
this artifact has 256 experts × 40 layers × 2 projections = **20 480** routed
expert tensors, the same order as the 20 480 buffer objects that plan cites.

Stated carefully: the *mechanism* was not isolated here. Allocator overhead per
buffer object and a larger unpacked layout would both present this way, and
`load_weight_tensor` takes the slab allocator, which on UMA is the default path.
What is established is the failure and its size, not which of those dominates.
Isolating it is M5's first measurement, not M4's.

## The chain this closes

- **§M7** measured the prize: cross-stream expert amortization is real —
  1.74× at N=16, 3.87× at N=64, 6.59× at N=128, all under this box's ~129-session
  VRAM ceiling (`2026-08-22-m7-amortization-measured.md`).
- **§M4** (here) shows the prize cannot be collected through unfusing, because
  the unfused path does not load.
- **§M5** is the unblock, and its plan is now on master (it previously existed
  only on an unreferenced commit).

So the ordering is M5 → M4 → M7's wall-clock half, and M7's weight-byte half is
already banked. That is a different order from the numbering, and it is worth
saying plainly: **M4 should not be attempted before M5 lands.**
