What survives when the model gets bigger

Eighteen quantized artifacts across 0.8B, 2B, 4B and 9B, scored against bf16 references on two held-out corpora. One finding from the 0.8B work does not generalize — and it fails in a way that names the fix.

The headline result

The embedding lever is a small-model phenomenon

Dropping the embedding table from 8-bit to 4-bit is the single largest size win available on a small model — at 0.8B it removes 1.44 bits per weight from the whole artifact. The 0.8B study concluded it was worth measuring before shipping. Across scale, that conclusion inverts: the same substitution costs 6.5× less KLD at 9B than at 0.8B, and saves 3× fewer bits.

Measured against each body's own KLD, the 4-bit embed costs +27% at 0.8B, +42% at 2B, +23% at 4B and +4.8% at 9B. At 9B it is very nearly free. Below 2B it is the dominant error term in the artifact.

The 0.8B→2B step rises before it falls. Parameter share alone does not explain the curve — 2B holds 27% of its parameters in the embed but pays more than 0.8B's 34% does. Whatever sets the cost, it is not share alone.

Why

The embedding table is the only tensor that gets no treatment

Every weight in the body is conditioned before it is quantized: an FWHT rotation to spread outliers, AWQ activation-aware scaling, then Hessian/LDLQ error feedback. The embedding table receives none of it. Asking for any Opus body routes the embed to plain affine Q8F16, in one explicit branch:

Three independent confirmations that this is structural, not an oversight: the eleven gather kernels in kernels/src/ cover bf16, f16, f32, hfq4g128, hfq4g256, q4k and q8 and include no Opus member; --embed-precision accepts only source | q8 | bf16 | f16 | hfq4; and neither quantize_q8f16 nor quantize_hfq4g256 calls cpu_fwht_256. A gather reads one arbitrary row, while Opus formats are rotated in 256-element groups along k — decodable, but by no kernel that exists.

So this study measured untreated 8-bit against untreated 4-bit. It is not a comparison of oq8+ against oq4+, and the numbers should not be read as one. The embed is also the tensor whose error matters most: it seeds the residual stream unnormalized.

That combination — the largest untreated tensor, in the position where error is most costly — is the headroom. The whole 27–42% penalty at 0.8B–2B sits on a table that has never been rotated. The work is a gather kernel, not a codec.

What generalizes

Calibration holds its value at every size

The opposite of the embedding result. Adding AWQ and Hessian/LDLQ to the same oq4.25 body cuts KLD by roughly half regardless of scale, with no downward trend — and at 4B and 9B it is free, landing at identical bits per weight (5.53 and 5.20) as the uncalibrated build.

This is worth stating plainly because it is the more useful half of the study: the expensive part of the pipeline — building a calibration artifact and running error feedback — pays the same dividend on a 9B model as on a 0.8B one. The cheap trick is what stopped scaling, not the principled one.

Infrastructure

Two things the study broke

OOM

The quantizer has no memory guard and takes the desktop with it

Quantizing 4B to qtip3 with greedy conditioning exhausted the shared UMA pool and triggered a global OOM: wireplumber, pipewire, dbus-daemon and the user session manager were all killed, twice, each time requiring a reboot. On this part GPU memory and system RAM are one pool, so a KFD allocation evicts the desktop. The loader already has exactly the right guard — load_mem_reserve_gib, documented as existing so a too-large load "fails as a refusal rather than a reaping" — and the quantizer has no equivalent. Running the remaining builds under choom -n 1000 made the job the OOM victim instead; both later failures were clean exit=137 with the session intact.

Scheduling

Quantization and QAT are not daemon operations

The daemon already schedules kld_eval, calibrate, train_drafter and train_lora. Quantization is a standalone binary and QAT is a training example, so neither queues behind the scheduler — they contend with it for one advisory lock. The daemon refuses rather than waits on a held lock, which silently produced empty scores for seven of eight artifacts in an early pass; the service takes the lock at boot, so offline builds fail until it is stopped by hand; and two pipelines raced on one output file because nothing arbitrates one-quantize-at-a-time.

What to do

Three consequences

Build a conditioned embedding gather. The embed is the largest untreated tensor and sits where error costs most. A rotated 4-bit gather format should be materially cheaper than HFQ4, and the payoff is concentrated below 4B, which is exactly where a 4-bit embed is currently unaffordable.

Replace the Q8F16 fallback with Bf16Lut3. Q8F16 is lossy; Bf16Lut3 is a lossless recoding already plumbed for this tensor — expand_bf16_index keeps a LUT3 head packed by default and its own comment notes the tied gather decodes it at load. Routing Opus bodies to a lossy fallback spends real KLD for a size win a lossless coding may match.

Don't spend the small-model embedding trick on large models. At 9B the 4-bit embed buys 0.48 bpw for +4.8% KLD, which is a reasonable trade; at 2B it buys 1.14 bpw for +42%, which is not. The recommendation in QUANTIZE.md should carry the scale caveat.
