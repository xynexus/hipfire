# gfx1201 27B AR per-kernel profile (2026-05-08)

Captured on hiptrx R9700 (gfx1201, 32 GB) via `profile_qwen35_mq4` against
`qwen3.5-27b.mq4`, branch `feat/gfx1201-kernel-tuning` HEAD `39a670f4`.
Profiling serializes kernel launches (sync after each launch); kernel/wall
ratio of 2.17x reflects that, not production behavior. Production decode
(non-profile mode, no hipGraph): 35.8 tok/s = 27.9 ms/step, dominated by
kernel time (~21.4 ms/step) + a smaller launch-overhead tail (~6.5 ms).

## Reading

R9700 peak DRAM BW per spec sheet ~640 GiB/s. Top kernels at 492-585 GiB/s
= 77-91% of peak — significant but not full BW saturation.

**Kernels in BW-saturated regime (>75% peak):**
- `gemv_hfq4g256` 584.9 GiB/s (91%) — hard ceiling, multirow null verified.
- `fused_qkvza_hfq4g256` 512.1 GiB/s (80%) — small headroom, gfx12 port may shave.
- `fused_qkv_hfq4g256` 501.5 GiB/s (78%) — similar.
- `gemv_hfq4g256_residual` 492.6 GiB/s (77%) — biggest slice; multirow R=1/2/4 null, BW-bound.

**Kernels in COMPUTE-bound regime (<20% peak BW):**
- `fused_rmsnorm_mq_rotate` 3.2 GiB/s — different optimization target (compute / FWHT).
- `fused_qk_l2_norm_scale_f32` 3.1 GiB/s.
- `gated_norm_f32` 9.9 GiB/s.
- `mq_rotate_x` 5.9 GiB/s.

## What this means for the gfx1201-kernel-tuning PRD

### PRD Item 2 (fused_qkv / fused_qkvza gfx1201 port) — JUSTIFIED

Combined 23.7% of kernel time on 27B AR. At 78-80% peak BW, headroom for
optimization is bounded but real. Best-case: fused_qkvza port to gfx12
WMMA-ish lane decomposition. Realistic: +1-3% wall on 27B decode.

### PRD Item 3 (fused_gate_up gfx1201 port) — UNCLEAR

`fused_gate_up` doesn't appear in the top-10 of this profile (the 27B AR
forward pass uses DeltaNet's `fused_qkvza` for LA layers and `fused_qkv`
for FullAttention layers — no gate_up shown). Confirm via prefill or
draft profile before committing to Item 3. May be a draft-side bottleneck
that this AR profile doesn't expose.

### Surfaced beyond PRD

`gemv_hfq4g256_residual` is the #1 hot kernel (36.3%) and has no
gfx1201-specific sister yet. Single-row dispatch already at 77% peak BW
so kernel-isa work is bounded, BUT the combined cost is large enough
that even a 5-10% per-kernel speedup nets 2-4% wall on 27B. Consider as
a new PRD item: profile `gemv_hfq4g256_residual` on gfx1201 for the
inner-loop dispatch and possible launch-overhead reductions.

Launch overhead is 54% of profile-mode wall (2.17x factor). In production
mode with `HIPFIRE_GRAPH=1` the gap is much smaller, but 867
launches/token is still a lot. If hipGraph + fused-launch reductions
could trim launch count by 30%, that's larger than any single kernel
optimization in the PRD. Out of PRD scope but plausibly the highest-ROI
lever for closing 192.6 -> 250.

## How to apply

Items 2 and 3 stay in the PRD with witnessed-bottleneck justification
(Item 2 explicitly, Item 3 contingent on a separate prefill/draft profile).
Item 4 Phase 2/3 (gfx12 MMQ workgroup-tile variants) targets prefill,
not decode — orthogonal to this profile but still PRD-valid.

For decode tok/s closure on 27B specifically: rocprof + reduce launch
count is plausibly the highest-leverage path. Recommended next step:
hipGraph capture coverage audit + `gemv_hfq4g256_residual` per-arch
profiling on gfx1201.
